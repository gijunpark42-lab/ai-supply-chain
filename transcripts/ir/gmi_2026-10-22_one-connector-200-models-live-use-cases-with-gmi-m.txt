What MCP is, and what GMI's server publishes

MCP, the Model Context Protocol, is an open standard for connecting a software client to outside tools and data. A provider runs a server that publishes a list of tools, each with a name, a description and a schema for its inputs. A compatible client reads that list at connection time, picks the tool a task needs, calls it with the required fields, and folds the result into its work. Before MCP, every model-to-service pairing was custom integration code: call the model, interpret its tool request, run the action, serialize the result, send it back. MCP replaces those one-off integrations with one shared contract.

The client is whatever you already work in: Claude Code, Claude on the web or desktop, Cursor, the Codex CLI, ChatGPT, or any other MCP client. The provider in this case is GMI Cloud.

The rhythm every job follows

Day to day the server follows one sequence, and you will see it in all three workflows below.

search_models for the task.

get_model to read the parameters: the field names, the accepted values, the defaults.

upload_media if the model needs one of your files as a public URL.

estimate_generation for a price.

Approval from you.

submit_generation, which returns a request ID.

get_generation until the status is complete, for anything asynchronous like video.

Three operating rules I set at the start of the video and kept through it. Read a model's parameters before preparing a request, because the schema is the only reliable description of what the model accepts. Quote every job and wait for approval before submitting it, because submission spends the balance. And treat a returned request ID as a successful submission, not a timeout: rendering happens on GMI's side and can take minutes, and the server hands back a tracking ID so the client can keep working.

Three jobs for a mug shop

For the video I played a small shop that sells ceramic mugs. Three jobs, each starting with one plain-language prompt. I ran them from Claude Code for the recording; the same prompts work unchanged from Cursor, the Codex CLI, ChatGPT, Claude on the desktop, or any other MCP client, because the tools and their schemas come from the server, not the client.

A five-second ad clip from one product photo. The prompt: "I have a JPEG at Downloads/mug.jpg. Find me a GMI model that animates a photo into a short video." The client called search_models, then get_model, which reads each candidate's declaration: the name of the starting-image field, the accepted resolutions and the duration range. For the model it recommended, kling-3.0-turbo-i2v, that is a required first_frame image, 720p or 1080p, and 3 to 15 seconds with a default of 5. upload_media moved the photo to GMI storage and returned a URL. estimate_generation quoted $0.50 for five seconds at 720p on kling-3.0-turbo-i2v; I asked for HappyHorse 1.1 instead and the quote came back at $0.70. submit_generation returned a request ID, get_generation reported processing, and a few minutes later the same call returned the finished clip.

Seven listing images from a CSV. The prompt: "Read products.csv in Downloads. For each row, generate one listing image on GMI using a fast, low-cost text-to-image model. Quote the full batch first and wait for my approval." The client searched the catalog, read four candidates (GPT Image 2.5, Hy Image 3.5, Gemini 3.1 Flash Image and Seedream), priced the batch on each, with the lowest quote at seven cents for all seven, and waited. I picked Gemini 3.1 Flash Image, which the catalog lists at $0.07 per image at the default resolution. The images came back in the order of the CSV rows and were saved by SKU.

One narration, three languages. The prompt: "I have a mug narration script in Downloads. Find a GMI text-to-speech model with natural voices. Tell me what English, Japanese and Spanish would cost. Wait for my approval before generating." Same rhythm: search, read parameters, estimate, approve, submit. I took the lowest-cost option, inworld-tts-2-flash, and all three voices were ready in one pass.

The account, the docs and support, from the same prompt box

Balance and spend. "What is our current balance on GMI, and what have we spent on text-model tokens this week, broken down by model?" get_account_summary returned the organization's balance in dollars and the token usage and cost for the period, ranked by the models with the most use. For my whole organization, everyone in the company, that was about $13,000 across 349,244 requests, text models only. Image, video and audio spend are not in that figure; ask for them separately, and treat the balance as a funding check rather than a live meter, because generation charges do not land on it immediately.

Documentation. "How does GMI rate-limit inference requests, and how should I handle an HTTP 429?" search_docs returned the matching sections from docs.gmicloud.ai with their links, so the client answered from the current documentation instead of from whatever it remembered.

Support. "A generation failed with an upstream-unavailable reference ID. Open a support request with the reference ID, model name and failure details." create_support_request filed a ticket carrying exactly the details support needs. Every call creates a new ticket, so file once.

Two things to know before you batch

Identical requests deduplicate. If the same model, prompt and parameters are submitted twice inside the dedupe window, you get the original job back instead of a second charge; the window is longer for video than for image. That protects you from an accidental double submit. It also means a deliberate second take of an identical request needs a new idempotency_nonce, or any change to the prompt or parameters, including the seed.

An estimate is a price, not a validation. estimate_generation prices a request, but the generation service validates it at submission. A parameter that only the service can catch can still get a quote, and the submission can still return a request ID and then end as failed. That is why get_model comes first in every workflow: the schema is where the accepted values live, and reading it is the cheapest check there is.
