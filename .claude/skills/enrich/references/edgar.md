### Workflow 2f — US companies via SEC EDGAR filings (`enrich edgar`)

US-listed names also file 8-Ks (material agreements, guidance changes, investor-day decks), a 10-K whose Business /
Risk Factors sections name their suppliers and whose notes disclose customer concentration, and 10-Qs.
`edgar_pull.py` saves them to `transcripts/edgar/` and builds a **low-noise queue**; only the queue is enriched.
Earnings-release 8-Ks (Item 2.02 only) are pulled but never queued — the call transcript for that quarter
(`enrich us`) is the richer source, and the release stays on disk only as a companion document for `verify_graph.py`.

**Trigger: the user says `enrich edgar`** — weekly, separate from the daily `enrich us` (user, 2026-09-26; the
status board recommends it once the last pull is more than 7 days old). Run the whole loop:
1. `python edgar_pull.py` — for every mapped US ticker: every 8-K since `--since` (default 120 days), the latest 10-K
   and the latest 10-Q (see the coverage table below). Existing files are skipped. Do NOT use `--force` on files that
   were already enriched unless you follow rule 2 of the completeness contract.
2. `python edgar_pull.py queue` — rebuilds `edgar/pending.json`. Each row carries `why` (which mapped counterparties
   or supply-chain terms it matched); `edgar/dropped.json` lists what was filtered out as noise (dividends, credit
   lines, personnel, buybacks, earnings releases). Enrich every queued row, reading the whole file. Never re-enrich a
   file that is not in the queue.
3. `python graph_build.py --sync` (runs `verify_graph.py` on the labels just applied — read its `[fail]`/`[warn]`
   lines), then `python edgar_pull.py done`.
4. Report per company: label, what was added, verify result.
If the queue is empty, say so and stop.

**Status table:** `edgar/STATUS.md` (regenerated by `queue` and `done`) lists EVERY pulled file as `queued` /
`enriched` / `dropped (noise)` with the reason. Read it before enriching; never enrich a `dropped` file unless the user
asks for that specific filing.

## Completeness contract — every filing is read ONCE, thoroughly, and never has to be reopened

(Set 2026-09-10 after round 1 turned out to have read extracts: exhibits cut at 15k chars, only 2 exhibits per 8-K,
10-K reduced to 12 customer paragraphs, supplier disclosures never saved.)

**1. What is saved (coverage — nothing is silently cut)**

| Form | File | Content |
|---|---|---|
| 8-K | `<TICKER>_8-K_<date>.txt` | every relevant Item in full + EVERY EX-99.x exhibit in full (safety cap 400k chars; a cut exhibit ends with `[exhibit truncated at … chars]` and its queue row starts with `TRUNCATED`) |
| 10-K | `<TICKER>_10-K_<date>_customers.txt` | every customer-concentration paragraph, whole + `## XBRL customer concentration` + `## XBRL segment revenue` |
| 10-K | `<TICKER>_10-K_<date>_supplychain.txt` | EVERY paragraph of the full 10-K that names another mapped company or carries a supplier / foundry / OSAT / contract-manufacturer / sole-source / supply-agreement / capacity-reservation / prepayment / purchase-commitment / backlog / RPO / capex term (whole, document order, no cap) |
| 10-Q | `<TICKER>_10-Q_<date>_segments.txt` | XBRL segment / product-line revenue with the year-ago comparison |
| 10-Q | `<TICKER>_10-Q_<date>_supplychain.txt` | same paragraph rule as the 10-K supplychain file, on the full 10-Q |

All text is built from the filing's own HTML (`document_text()` → `html_to_text()`), never from edgartools'
`.text()`, whose renderer shortens some blocks with "..." (found 2026-09-10: Hut 8's "Right of First Offer for up to an
additional 1,000 M…"; a Credo EX-99.1 lost ~9% of its text). Table cells are kept apart with ` | `, page numbers and
"Table of Contents" lines are dropped.
8-K Item sections are split only at Item HEADINGS (a line that starts with "Item N.NN"); a cross-reference inside a
sentence ("as described in Item 9.01") no longer opens a section — it used to, and the rest of the real section was
dropped whenever that item was not kept (found 2026-09-11: 169 sections in 151 8-Ks; Baker Hughes 05-19 Item 5.02 went
from 186 to 2,128 chars after the fix).
Paragraph matching runs on `paragraphs()`: blocks the SEC text breaks at a page boundary mid-sentence are re-joined
first, so a match on the first half always keeps the continuation (found 2026-09-10: Dominion's Chesterfield paragraph
lost "…Commission denied the reconsideration petition and affirmed its November 2025 approval").
Tables are judged WHOLE (`table_blocks()`): consecutive table rows form one block, and a supplychain file keeps every
segment / revenue / capex / backlog / RPO / customer / end-market / capacity table with the sentence that introduces it
(the customers file keeps customer / end-market tables). Whitespace inside the HTML source is collapsed and a `<p>` inside
a cell never breaks the row (found 2026-09-11: the first HTML re-pull filtered tables row by row and silently dropped
them — segment revenue, segment EBITDA, capex and backlog tables vanished from 117 of 135 10-K supplychain files; only a
verify failure on old entries revealed it). Pages filed as pictures leave `[image: <src> — not text]` where they sit.
XBRL percentages are printed with one decimal as filed (before 2026-09-10 they were rounded to whole numbers, so a
filed 9.6% read "10%"); dollar facts are shown in $M / $B with the filed value rounded to two decimals.
All files of one filing share its label (`[Company] 10-K (MM-DD-YYYY)`), so verify_graph checks an entry against all of them.

**2. Enriched files are immutable.** A better extraction idea becomes a NEW file kind (new suffix), which the queue
picks up as new rows — never a rewrite of an enriched file. If an enriched file must be re-pulled (an extractor bug),
first copy every file listed in `edgar/done.json` to a snapshot, re-pull, and enrich ONLY the delta (text the snapshot
did not contain), never the whole file again.
**2b. After ANY re-pull, run a number-coverage test before enriching the delta:** every number in the snapshot file
must still be in the new file (a delta looks only for NEW text and can never see LOST text). A lost number that the old
file held in an in-scope passage (segment, capex, backlog, customer, supply) is an extractor regression — fix the
extractor and re-pull; lost numbers from out-of-scope tables (balance sheet, cash flow, purchase-price allocation) or
from the old renderer's cut-off cells ("1,230…") are listed in the run report, not chased.

**3. Read every page.** `python -X utf8 utils/show_filing.py <file> [page]` until `=== END OF FILE ===`. Never the Read
tool on `transcripts/edgar/` — exhibits are single lines of tens of thousands of characters and get cut.

**4. Every queue row gets a disposition** in the run's report: the patch file, or `no patch` + the reason (financing,
governance, restated call figure, out of scope, …). A TRUNCATED row is reported as such.

**4b. The noise filter only ORDERS the work — it never replaces reading** (user decision 2026-09-11, after round 1–2
had silently skipped 333 of 486 8-Ks). Every file in `edgar/dropped.json` is read once, to the last page, in a triage
pass with the same enricher + verifier pattern:
- earnings-release-only 8-K whose quarter's call is already enriched → add only facts the call entries do not state
  (typically named deals, segment tables with printed labels); whose call is NOT enriched → extract it like a queued row;
- personnel / financing / dividend / governance filings → read and confirm nothing in scope (or extract what is);
- then `python edgar_pull.py done --with-dropped` marks the triaged files as read, so they never come back.

**5. Two-stage accuracy, always.**
- Enricher writes `patches/edgar_<file stem lowercased>.json` and runs `python -X utf8 utils/check_edgar_patch.py <patch>`
  until `RESULT: clean` (also fix `number_derived`, `number_near_miss`, `counterparty_not_in_source` warnings).
- An independent verifier re-reads every filing, re-checks every entry and confirms every skip; corrects / removes /
  adds in the patch.
- Only then one `graph_build.py --sync`; `verify_graph` must report 0 fail, and no entry may sit on two nodes.
- `edgar_pull.py done` last.

**6. Multi-agent recipe (the default — N up to 20, fewer for a small queue).** `python -X utf8 utils/edgar_batches.py <N>`
splits `edgar/pending.json` by company (a company never spans two agents) into `edgar/batches/batch_NN.json`. One enricher per batch writes only its
own patches; one verifier per batch starts when its enricher finishes; only the coordinator runs `graph_build.py`.

## What to extract (accuracy first, ADD-only, same JOB 1–5 rules as Workflow 2)

- **8-K Item 1.01 / 7.01 / 8.01 + exhibits** — a supply, purchase, manufacturing, licence, lease or collaboration
  agreement with a *named* counterparty → `contracts` entry on the matching edge (or a new edge only if the filing
  states the relationship explicitly). Capacity expansions, backlog, order and guidance figures → `quarterly_data` on
  the filer. Skip financing, governance, compensation and deal terms even when the row is queued; a financing deck can
  still carry a real supply-chain fact (a named data-center lease: MW, term, contracted revenue).
- **10-K customer concentration** — every "[named customer] accounted for X% of revenue in fiscal YYYY" sentence →
  `contracts` entry on the edge to that customer with `type: "10-K customer concentration"`, the percentage and fiscal
  year. Anonymous customers ("Customer A") go on the filer as `quarterly_data`, never mapped to a name.
- **XBRL sections** (`## XBRL customer concentration`, `## XBRL segment revenue`) are machine-read facts, copied as
  filed — authoritative over the prose, BUT check for mis-tags before using them: receivables tagged as revenue, "RPO"
  lines that carry segment revenue, a percentage that cannot be true next to the filing's other figures. Mis-tagged →
  omit, never guess.
  - Concentration lines: use the *revenue* lines; accounts-receivable lines are context only.
  - Segment lines → one `quarterly_data` entry per relevant segment (data center / AI / networking / optical /
    semiconductor / equipment / power generation & grid / cooling / cloud); skip consumer, automotive, geography-only
    splits. Keep the dollar figure, the period and the YoY as written; never annualise or re-derive.
- **Supplychain paragraphs (10-K / 10-Q)** — a named supplier the filing says it uses ("we utilize foundries such as
  TSMC", "Amkor and ASE package our ICs", "we purchase memory from SK Hynix") → `contracts` on the SUPPLIER → FILER
  edge (`type: "10-K supplier disclosure"` / `"10-Q supplier disclosure"`), existing matching edge first, a new edge
  only when both companies are players in that chain, otherwise `quarterly_data` on the filer naming the supplier.
  Named customers, named agreements, backlog / RPO and capex figures in these paragraphs are in scope too. Competitor
  lists, generic risk text, accounting prepayments and exhibit indexes are noise — skip them.
- Never infer a relationship from a product mention alone; the filing must state it.

## Settled rulings (2026-09-10) — apply them, do not re-decide

- **Edge meaning must match.** A contract goes on an edge only if the fact describes that edge's `relationship` in
  that direction. The opposite flow → the correct-direction edge when both companies are players in that chain, else
  `quarterly_data` on the filer with the counterparty named.
- **Existing edges may target companies outside the chain file** (edges merge across chains by name) — contracts on
  them are valid. A NEW edge needs both companies as players in that chain.
- **Placement.** Company-wide facts (total revenue, concentration, company guidance) → the placement that holds the
  company's company-wide call entries (the slot-tagged ones). A segment that maps to exactly one placement → that
  placement; an ambiguous segment → the company-wide placement. Each fact on ONE node, never copied across chains.
- **No restated duplicates.** Skip numbers + period already stated on that node by the earnings call; the year-ago
  comparison alone may be written when it is the only new figure. Also skip facts the same-day company IR release
  already put on the node (`enrich us` enriches releases daily; an 8-K exhibit is usually that release).
- **M&A / merger filings:** only operating capacity facts not already in the chain — never the deal price,
  pro-forma combined-company figures or proxy material.
- **No implied generation.** A deal fact whose filing names no product generation → the edge already recording that
  deal, else the least generation-specific chain that holds the edge.
- **List-only mentions** (a licensee list, a customer list) support only an edge whose relationship is exactly that kind.
- **Unnamed purchase obligations / commitments:** in scope only when the filing ties them to supply (inventory,
  wafers, components, manufacturing capacity, a named-type supply agreement deposit) or to capex — written as
  `quarterly_data` with that scope stated. Generic contractual-obligation totals that mix leases, services, software
  or taxes (e.g. Apple's company-wide purchase obligations) are out.
  Test for a total whose definition lists several kinds: KEEP it (scope written out) when the filing's own text says it
  is mostly / primarily inventory, components or capacity, or ties the total or its increase to securing supply
  (Google "mostly technical infrastructure and inventory", HPE "to secure strategic component supply", Broadcom
  "primarily inventory"); REMOVE it when the filing gives only the generic mixed definition (HPE 10-K $3.3B, AMD,
  Intel "other purchase obligations", Arista 10-K). Lease or lease-revenue figures tied to data-center capacity are not
  purchase obligations and are judged as capacity facts.
- **Unlabelled chart / deck values:** a figure whose period is not printed as text next to it (spreadsheet date
  serials, chart bars, a table cut mid-cell) is never used — not even when another figure "cross-checks" it. Use the
  same number from a filing section that prints the period, or leave it out.
- **`slot`:** omit by default; only on an 8-K entry newer than every same-slot entry of that node; never on 10-K /
  10-Q. Never create a second same-date entry with the same slot (derive.py `latest_only` keeps both — ambiguous).
- **Renamed node** (the file's label prefix ≠ the node name) → `python edgar_pull.py --tickers <T> --force` before enriching.
- **New nodes** only with the litmus test and an independent Claude verifier's approval (enrich skill JOB 3; the user
  handed approval to Claude on 2026-09-26). Decided earlier by the user: Fluidstack added; Core42, AES and Nanjing
  Casela are NOT to be added.

## Labels

Use the file's `# source label:` header verbatim: `[Company] 8-K (MM-DD-YYYY)`, `[Company] 10-K (MM-DD-YYYY)`,
`[Company] 10-Q (MM-DD-YYYY)` (`Lumentum 8-K (08-11-2026)`). The date is the filing date. Same label on every node /
edge touched by that filing; never mix it with the call label of the same quarter.

File format `transcripts/edgar/<TICKER>_8-K_<YYYY-MM-DD>.txt`: header lines, then `## Item N.NN` sections and
`## Exhibit EX-99.x (...)` sections (whitespace-collapsed, one line each). The 10-K / 10-Q files are described in the
coverage table above.
